# DomePlayer: เครื่องเล่นวิดีโอโดม 6 โปรเจคเตอร์ (เฟส 1)

ตอนนี้ทำได้: **เล่นไฟล์ Domemaster วน loop เต็มจอบนจอเดียว** ถอดรหัสด้วย GPU (NVDEC) วาดผ่าน shader ของเราเอง
และมีหน้าสถิติ FPS / เฟรมที่ drop (กด F1 เปิดหรือปิด) ค่าตั้งทั้งหมดอยู่ใน `config.json`

---

## 1. Tech stack ที่เลือกและเหตุผล

**Python 3.12 + libmpv (render API) + GLFW + moderngl (OpenGL 3.3)** ตรงกับที่คิดไว้ แต่ปรับรายละเอียด 3 จุด

| ชิ้นส่วน | หน้าที่ | ทำไมเลือก |
| --- | --- | --- |
| **libmpv** (`libmpv-2.dll`) | เปิดไฟล์, ถอดรหัส H.264 ด้วย **NVDEC**, จับเวลาเฟรม, เสียง, loop | `hwdec=nvdec` ส่งเฟรมจาก NVDEC เข้า OpenGL texture โดยตรงผ่าน CUDA interop ไม่ต้องก๊อปกลับมาที่ CPU ซึ่งสำคัญมากที่ 3840×3840 |
| **mpv render API** | ให้ mpv วาดเฟรมลง *texture ของเรา* (ไม่ใช่หน้าต่างของ mpv) | เราจึงเอา texture ไปผ่าน shader ตัด fisheye / warp / blend ได้เอง จุดนี้คือเหตุผลที่ไม่ใช้ `mpv.exe` ธรรมดา |
| **GLFW** | สร้างหน้าต่างไร้ขอบเต็มจอ เลือกจอตามเลข Windows (`\\.\DISPLAYn`) | คุมตำแหน่งหน้าต่างทีละจอได้แม่น เฟสหลังต้องเปิด 3–4 หน้าต่างต่อ process |
| **moderngl** | เขียน shader / texture / FBO แบบสั้นๆ | โค้ด warp mesh และ edge blend ในเฟส 2 จะสั้นกว่า PyOpenGL มาก |
| **Pillow** | วาดตัวหนังสือสถิติ | วาดเองแทน OSD ของ mpv เพราะ OSD ของ mpv จะโดน warp ไปกับภาพในเฟสหลัง |

จุดที่ปรับจากแผนเดิม:
1. **ใช้ GLFW แทน pyglet หรือ pygame:** เลือกจอด้วยเลข `\\.\DISPLAYn` ได้ตรงๆ และตั้งให้หน้าต่างไม่ย่อเองตอนเสียโฟกัสได้
2. **ให้ mpv วาดลง texture ขนาดเต็ม 3840×3840 (+ mipmap)** แล้วค่อยย่อด้วย shader ของเรา ไม่ให้ mpv ย่อให้
   เพราะเฟสหน้าโปรเจคเตอร์แต่ละตัวต้องดึงพิกเซลจากคนละส่วนของ fisheye
3. **1 process ต่อ 1 GPU** ใส่ช่องไว้แล้วตั้งแต่ตอนนี้ (`video.cuda_device` และการเลือกจอตามเลข)

ทางเลือกอื่นที่พิจารณาแล้วไม่เลือก:
- **C++ + FFmpeg/NVDEC + D3D11:** เร็วที่สุด แต่พัฒนาและแก้หน้างานช้ากว่ามาก ถ้าเฟส 1 ทดสอบแล้ว Python ไม่พอค่อยย้าย (ส่วน shader ย้ายตามไปได้เกือบหมด)
- **TouchDesigner / Resolume / VIOSO:** ทำได้เร็วแต่เสียค่าลิขสิทธิ์ และ TouchDesigner รุ่นฟรีจำกัดความละเอียดไว้ที่ 1280×1280
- **Unity / Unreal:** หนักเกินงานนี้ และการ sync วิดีโอข้ามเครื่องทำยากกว่า

ข้อมูลฮาร์ดแวร์ที่เช็กแล้ว:
- NVDEC ของ Quadro P620 (Pascal) ถอด H.264 ได้สูงสุด 4096×4096 ไฟล์ 3840×3840 จึงอยู่ในเกณฑ์
- หน่วยความจำ GPU ที่ใช้โดยประมาณ: texture วิดีโอ+mipmap ~80 MB บวกบัฟเฟอร์ NVDEC อีก ~0.4–0.5 GB รวมยังต่ำกว่า 2 GB ต่อใบสบายๆ

## 2. ในโฟลเดอร์มีอะไร

```
DomePlayer/
  1-SETUP.bat            ← ดับเบิลคลิกครั้งแรกครั้งเดียว (ติดตั้ง)
  2-RUN.bat              ← ดับเบิลคลิกเพื่อเล่น (ไม่มีหน้าต่างดำ)
  RUN-DEBUG.bat          ← เล่นแบบมีหน้าต่างดำโชว์ข้อความ ใช้ตอนหาสาเหตุปัญหา
  IDENTIFY-MONITORS.bat  ← โชว์เลขจอตัวใหญ่บนทุกจอ
  config.json            ← ค่าตั้ง (แก้ด้วย Notepad)
  domeplayer/            ← โค้ดโปรแกรม
  tools/get_libmpv.py    ← ตัวดาวน์โหลด libmpv-2.dll (1-SETUP เรียกให้เอง)
  lib/                   ← libmpv-2.dll จะมาอยู่ที่นี่
  logs/                  ← domeplayer.log, monitors.txt
```

## 3. ติดตั้งจากซอร์สโค้ด (ทำครั้งเดียว ใช้เน็ตตอนติดตั้ง)

> **ถ้าใช้ `DomePlayer.exe` (โฟลเดอร์ offline) ข้ามหัวข้อ 3 นี้ทั้งหมด** แค่ก๊อปโฟลเดอร์ไปไว้ที่ `C:\DomePlayer` แล้วดับเบิลคลิก `DomePlayer.exe`

**ขั้นที่ 1: ติดตั้ง Python**
1. เปิด https://www.python.org/downloads/windows/ แล้วกดดาวน์โหลด **Python 3.12.x "Windows installer (64-bit)"**
2. เปิดไฟล์ที่โหลดมา **ติ๊กช่อง "Add python.exe to PATH"** ที่ด้านล่างของหน้าแรก
3. กด **Install Now** รอจนขึ้นว่า "Setup was successful" แล้วกด Close

**ขั้นที่ 2: เช็กไดรเวอร์การ์ดจอ**
- ควรเป็นไดรเวอร์ NVIDIA RTX/Quadro รุ่นใหม่ โหลดได้จาก nvidia.com (เลือก Quadro P620)
- ถ้าเปิดวิดีโอใน YDome ได้อยู่แล้ว ส่วนใหญ่ข้ามขั้นนี้ได้

**ขั้นที่ 3: ก๊อปโฟลเดอร์**
- ก๊อปโฟลเดอร์ `DomePlayer` ทั้งโฟลเดอร์ไปไว้ที่ `C:\DomePlayer` (ใช้ path ที่ไม่มีภาษาไทยหรือช่องว่างจะปลอดภัยที่สุด)

**ขั้นที่ 4: ติดตั้ง**
1. เปิดโฟลเดอร์ `C:\DomePlayer` แล้ว **ดับเบิลคลิก `1-SETUP.bat`**
2. ถ้า Windows ขึ้นหน้าจอสีฟ้า "Windows protected your PC" ให้กด **More info** แล้วกด **Run anyway**
3. รอจนขึ้น `===== SETUP FINISHED OK =====` (ราว 1–5 นาที) แล้วกดปุ่มอะไรก็ได้เพื่อปิด
4. ถ้าขึ้น `SETUP FAILED` ให้ถ่ายรูปหน้าจอส่งมา

> ถ้าขั้นดาวน์โหลด libmpv ไม่ผ่าน (เช่นเน็ตบล็อก GitHub) ทำเองได้ดังนี้: เปิด
> https://github.com/shinchiro/mpv-winbuild-cmake/releases แล้วโหลดไฟล์ชื่อ
> `mpv-dev-x86_64-วันที่-git-รหัส.7z` (ไม่ใช่ตัวที่มี `-v3-` และไม่ใช่ `aarch64`) เปิดด้วย 7-Zip
> แล้วก๊อป `libmpv-2.dll` ไปใส่ในโฟลเดอร์ `lib`

**ขั้นที่ 5: ดูเลขจอ**
- ดับเบิลคลิก `IDENTIFY-MONITORS.bat` ทุกจอจะขึ้นเลขตัวใหญ่ 20 วินาที (คลิกเพื่อปิดก่อนได้)
- เลขนี้คือค่าที่ใส่ใน `"monitor"` ของ `config.json`
- เลขควรตรงกับเลขใน Windows Settings → Display แต่ถ้าไม่ตรง **ให้ยึดเลขจาก IDENTIFY**
  (รายการจอทั้งหมดถูกบันทึกไว้ใน `logs\monitors.txt` ด้วย)

**ขั้นที่ 6: แก้ config.json**
- คลิกขวาที่ `config.json` → **Open with → Notepad**
- แก้ `"path"` ให้ชี้ไฟล์วิดีโอ (ค่าเริ่มต้นชี้ไฟล์ของ YDome ไว้ให้แล้ว) และแก้ `"monitor"` เป็นเลขจอที่ต้องการ
- กด Ctrl+S เพื่อบันทึก

**ขั้นที่ 7: เล่น**
- ดับเบิลคลิก **`2-RUN.bat`** ภาพจะขึ้นเต็มจอที่เลือกพร้อมหน้าสถิติมุมซ้ายบน
- ถ้าไม่มีอะไรขึ้นเลย ให้ลองเปิด `RUN-DEBUG.bat` แทน แล้วอ่านข้อความในหน้าต่างดำ

## 4. ปุ่มกด

| ปุ่ม | ทำอะไร |
| --- | --- |
| **F1** | เปิด/ปิดหน้าสถิติ |
| **Space** | หยุดชั่วคราว / เล่นต่อ |
| **Home** | กลับไปต้นวิดีโอ (และล้างตัวนับสถิติ) |
| **Esc** | ปิดโปรแกรม (ถ้าอยู่ในโหมดปรับมุม จะออกจากโหมดปรับมุมแทน) |
| **T** | สลับ ตารางทดสอบ / ขาวทั้งจอ / ปิด (ตาราง: แต่ละจอสีต่างกัน มีเลขจอตรงกลาง) |
| **1–9** | โชว์เฉพาะจอเลขนั้น (จออื่นดำ) |
| **0** | โชว์ทุกจอ |
| **E** | เข้า/ออกโหมดปรับมุมของจอที่โชว์อยู่ |
| **Ctrl+S** | บันทึกการปรับมุมและความสว่างลง `config.json` |

เปลี่ยนปุ่ม F1 / Space / Home / Esc ได้ใน `config.json` หัวข้อ `"keys"` (ใส่ `""` เพื่อปิดปุ่มนั้น เช่นปิด Esc ตอนเปิดใช้งานจริง)

### โหมดโดม (ค่าเริ่มต้น): โปรเจคเตอร์แต่ละตัวฉายคนละส่วนของโดม แล้วต่อกันเนียน

ห้องนี้ติดโปรเจคเตอร์ไว้รอบร่องไฟ แต่ละตัวยิงข้ามไปอีกฝั่งของโดม ภาพจึงซ้อนกันบางส่วน ไม่ได้ทับกันพอดี
โปรแกรมใช้กล้องคำนวณให้เองว่าแต่ละตัวต้องฉายส่วนไหนของวิดีโอ แล้วไล่ความสว่างตรงที่ซ้อนกันให้กลืนเป็นภาพเดียว
นอกวงกลมโดมจะเป็น**สีดำ** (แบบเดียวกับ Screenberry)

1. ตั้งกล้อง R50 (เลนส์ 10mm) **ไว้กลางห้อง หันขึ้นตรงๆ** ให้เห็นโดมทั้งวง (วางบนพื้นได้ถ้าเห็นไม่ครบ) ตั้งกล้องตามหัวข้อด้านล่าง
2. เปิด DomePlayer ติ๊ก "ใช้หลายจอพร้อมกัน" จอ `3, 6, 2, 4, 5, 1` แล้วกด เล่น
3. กด **K** แล้ว **K** ถ่ายลายทีละเครื่อง (ประมาณ 2–3 นาที ห้องมืด ห้ามขยับกล้อง)
   ครั้งแรกโปรแกรมจะหาขอบโดมเอง (วงกลมใหญ่ที่สุดที่มีแสงครบ)
4. **กำหนดขอบวงกลม:** กด **T** จนเป็นสีขาว แล้วกด **C** ดูภาพกล้อง จะเห็นวงกลมบนภาพโดม (สีฟ้า = โปรแกรมหาเอง, สีเหลือง = กำหนดเองแล้ว)
   - **ลูกศร** = เลื่อนวงกลม, **+ / -** = ขยาย/ย่อ (กด **Shift** ค้างไว้ = ทีละ 10)
   - **, .** (ปุ่มลูกน้ำ / จุด) = หมุน "FRONT" (เส้นสีแดง) ไปทางที่ต้องการให้เป็นด้านหน้าของวิดีโอ (ขอบล่างของไฟล์ Domemaster จะไปอยู่ทางเส้นนี้)
   - **A** = กลับไปใช้ขอบที่โปรแกรมหาเอง
   - **Ctrl+S** = บันทึก แล้วคำนวณใหม่จากภาพที่ถ่ายไว้ทันที **ไม่ต้องถ่ายใหม่**
   ให้วงกลมทับขอบโดมจริงพอดี ถ้าอยากให้ขอบภาพหลบร่องไฟ ก็ย่อเข้ามาอีกนิด
5. กด **C** ปิดภาพกล้อง แล้ว **T** ดู ตาราง / ขาว / วิดีโอ, **U** เปิด/ปิดผลเพื่อเทียบ

ค่าที่เกี่ยวข้องใน `config.json` หัวข้อ `"calibration"`:
`"mode": "dome"` (ถ้าทั้ง 6 ตัวฉายทับที่เดียวกันจริงๆ ใช้ `"stack"`), `"dome_circle"`, `"dome_front_deg"`,
`"lens_mm": 10` (ถ้าซูมเลนส์ไปที่อื่น ให้แก้ตาม, 0 = ไม่แก้เลนส์)
และหัวข้อ `"mask"`: ทำให้ดำนอกวงกลมของวิดีโอ (`"radius": 1.0` = ขอบ Domemaster, เล็กลง = ตัดขอบเข้ามา, `"feather"` = ความนุ่มของขอบ)

### โหมด stack: ฉายภาพเดียวกันทั้ง 6 ตัว ซ้อนทับพื้นที่เดียวกัน (`calibration.mode: "stack"`)

เปิดได้ที่หน้าต่างเริ่มต้น ติ๊ก **"ใช้หลายจอพร้อมกัน"** แล้วใส่เลขจอ เช่น `3, 6, 2, 4, 5, 1`
(หรือใน `config.json`: `"stack": {"enabled": true, "monitors": [3, 6, 2, 4, 5, 1]}`)

- โปรแกรมเปิด**หน้าต่างเดียวคลุมทุกจอ** ถอดรหัสวิดีโอครั้งเดียว แล้ววาดภาพเดียวกันลงทุกจอใน swap เดียว
  ทุกโปรเจคเตอร์จึงได้**เฟรมเดียวกันเสมอ** ไม่ต้อง sync ระหว่างโปรแกรม
- ส่วนที่ยังคลาดได้คือจังหวะสแกนจอของการ์ด 2 ใบ (ไม่มี Quadro Sync) ซึ่งต่างกันได้ไม่เกิน 1 รอบจอ
  ใช้ **ตารางทดสอบ (T)** เช็กได้: เส้นสีขาวที่หมุนอยู่ ถ้าเห็นเป็น 2 เส้นแปลว่าการ์ดสองใบแสดงคลาดกัน
- ตั้งทุกจอให้ refresh rate เท่ากัน (แนะนำ 50 Hz สำหรับวิดีโอ 25fps) ถ้าไม่เท่ากันโปรแกรมจะขึ้นเตือน

**วิธีปรับให้ 6 ภาพทับกันสนิท**
1. กด **T** ให้ขึ้นตารางทดสอบ เลือกตัวหนึ่งเป็นตัวหลัก (เช่นจอ 3) แล้วปรับตำแหน่งที่ตัวเครื่องให้ดีที่สุดก่อน
2. กดเลขจอที่จะปรับ เช่น **6** แล้วกด **0** สลับกันดู เพื่อเทียบกับตัวหลัก
   (หรือปิดโปรเจคเตอร์ตัวอื่นไว้ เหลือแค่ตัวหลักกับตัวที่กำลังปรับ)
3. กด **6** แล้วกด **E** เข้าโหมดปรับมุม จะเห็นวงกลมที่มุมทั้ง 4
   - ลากมุมด้วยเมาส์ หรือกด **Tab** เลือกมุม แล้วใช้ลูกศรขยับทีละ 1 px (**Shift**+ลูกศร = 10 px)
   - **+ / -** ปรับความสว่างของตัวนั้น ให้เท่ากับตัวอื่น
   - **R** รีเซ็ตกลับค่าเริ่มต้น
4. กด **Ctrl+S** บันทึก แล้วทำแบบเดียวกันกับจอที่เหลือ
5. กด **T** ปิดตารางทดสอบ แล้วกลับมาดูวิดีโอ

ค่าที่ปรับไว้เก็บใน `config.json` หัวข้อ `"outputs"` ตามเลขจอ (มุมเป็นสัดส่วน 0–1 ของจอ)
ถ้าเลขจอใน Windows เปลี่ยน (เช่นถอดสายแล้วเสียบใหม่) ให้เช็กด้วย "โชว์เลขจอ" อีกครั้ง

### ปรับอัตโนมัติด้วยกล้อง (Canon EOS R50): ตำแหน่ง + ความสว่าง

โปรแกรมฉายลายขาวดำทีละเครื่อง ถ่ายด้วยกล้อง แล้วคำนวณเอง 2 อย่าง
1. **ตำแหน่ง:** ดัดภาพแต่ละเครื่องหลายจุด (mesh 64×40) ให้ทับเครื่องหลัก (จอแรกในรายการ) ทุกพิกเซล
2. **ความสว่าง:** ลดความสว่างทีละพิกเซลของแต่ละเครื่อง ให้แสงรวมเรียบเป็นเนื้อเดียวกัน
   (ลบจุดสว่างกลางภาพ ขอบมืด และขอบภาพของแต่ละเครื่องที่เหลื่อมกัน) ไม่มีการเพิ่มความสว่าง มีแต่ลด

**ไม่ต้องใช้ Canon SDK** ใช้โหมด webcam ของกล้อง:
1. กล้อง: เมนู Set-up → **Choose USB connection app** → **Video calls/streaming** แล้วต่อสาย USB เข้าเครื่อง Dell
2. หมุน dial เป็น **Movie** ตั้ง **Movie manual exposure**, ISO คงที่, white balance คงที่, โฟกัส **MF** ให้ชัดที่โดม
3. ใช้ไฟบ้าน (R50 ใช้ DC coupler **DR-E18** + adapter **AC-E6N**, สาย USB ไม่จ่ายไฟให้กล้อง) ปิด Auto power off
   (ค่ากล้องบางอย่างจะหายเมื่อปิดกล้อง แนะนำบันทึกไว้ในโหมด C) กล้องส่งภาพทาง USB ได้ 1920×1080 30 fps ตั้งกล้องบนขาตั้งให้เห็นภาพที่ฉาย**ทั้งหมด** (เลนส์ 10mm) ห้ามขยับจนเสร็จ
4. ปิดไฟห้อง

ในโปรแกรม (โหมด stack หรือโหมดโดม):
1. กด **C** ดูภาพจากกล้อง (ขึ้นกลางจอ) ถ้าไม่ใช่ R50 กด **[** หรือ **]** เปลี่ยนกล้อง
   ตัวเลข "over-exposed" ต้องเป็น 0% ตอนฉายภาพปกติ ถ้าเกินให้ลด ISO/speed ที่กล้อง
2. กด **K** แล้ว **K** อีกครั้ง เพื่อเริ่ม (6 เครื่องใช้ประมาณ 2–3 นาที ห้ามเดินผ่านหน้ากล้อง) กด **Esc** เพื่อยกเลิก
3. เสร็จแล้วโปรแกรมคำนวณเอง บันทึกในโฟลเดอร์ `calibration` แล้วขึ้นตารางทดสอบให้ดู
4. กด **T** สลับ ตาราง / ขาวทั้งจอ (ดูความเรียบของแสง) / วิดีโอ และกด **U** เปิด/ปิดผล เพื่อเทียบก่อน-หลัง

ถ้าขึ้นข้อความว่ากล้องสว่างเกิน (over-exposed) หรือมืดเกิน ให้ปรับที่กล้องแล้วกด K K ใหม่
ถ้าย้ายโปรเจคเตอร์หรือเปลี่ยนความละเอียดจอ ต้อง calibrate ใหม่
ยังปรับ 4 มุมของ**เครื่องหลัก**ได้ (E) เพื่อเลื่อน/ซูมทั้งภาพ เครื่องอื่นจะตามเอง

### แผงควบคุม (ตั้งแต่เวอร์ชัน 0.3)

กด **เล่น** แล้วหน้าต่างเริ่มต้นจะเปลี่ยนเป็น **แผงควบคุม** บนจอคนคุม (เปิดเองทีหลังได้ด้วยปุ่ม "แผงควบคุม")
- บอกเป็นภาษาไทยว่าตัวเล่นกำลังทำอะไร: เล่นวิดีโอ / ตารางทดสอบ / กำลังถ่ายลายกี่ % / ผล calibrate ล่าสุด และคำเตือน
- มีปุ่มแทนปุ่มคีย์บอร์ดทุกปุ่มที่ใช้ตอนติดตั้ง (T, C, U, เริ่ม calibrate, เลื่อน/ย่อ/ขยายวงกลมโดม, บันทึกวงกลม, ปิดการฉาย)
  จึงไม่ต้องอ่านข้อความภาษาอังกฤษบนโดม และไม่ต้องกังวลว่าคีย์บอร์ดจะ "หลุด" จากหน้าต่างเล่น
- ตอนเปิดหน้าภาพกล้อง จะเห็นภาพกล้องเดียวกันบนแผงควบคุมด้วย
- ปิดแผงควบคุมได้ การฉายไม่หยุด

### เลือกจอให้เอง และการจำช่องเสียบ (ตั้งแต่เวอร์ชัน 0.3)

Windows เปลี่ยน "เลขจอ" ได้เองเมื่อโปรเจคเตอร์เปิดช้า ถอดสาย หรือมีจอเพิ่ม (หน้างานจริงเลขเปลี่ยน 3 ครั้งใน 30 นาที) โปรแกรมจึง
- มีตัวเลือก **เลือกจอให้เอง** (`stack.auto`): ใช้ทุกจอยกเว้นจอหลักของ Windows (จอคนคุม) ไม่ต้องพิมพ์เลขจอ
- จำ **ช่องเสียบของการ์ดจอ** ของโปรเจคเตอร์แต่ละเครื่องไว้กับค่า calibrate ถ้าวันหลัง Windows ให้เลขจอใหม่ ค่า calibrate จะตามไปถูกเครื่องเอง
  (ถ้าย้ายสายไปเสียบช่องอื่นของการ์ดจอ ต้อง calibrate ใหม่)
- ถ้าจอคนคุมอยู่ "ระหว่าง" จอโปรเจคเตอร์ในการจัดจอของ Windows หน้าต่างเล่นจะเว้นจอนั้นไว้ ยังใช้งานได้ตามปกติ
- ตอน calibrate ถ้ากล้องมองไม่เห็นจอไหนเลย (โปรเจคเตอร์ปิดอยู่ หรือจอนั้นไม่ใช่โปรเจคเตอร์โดม) โปรแกรมจะ **ข้ามจอนั้น** แล้วทำจอที่เหลือต่อ
  จอที่ถูกข้ามจะเป็นสีดำตอนฉาย และมีคำเตือนบอกเลขจอ

### calibrate ด้วยกล้องที่อัดวิดีโอ: Insta360 / กล้อง 360 / มือถือ (ตั้งแต่เวอร์ชัน 0.3)

ใช้เมื่อกล้อง USB เห็นโดมไม่ครบ (ห้องนี้เพดานเตี้ย กล้อง R50 เลนส์ 10mm เห็นโดมได้ราว 63%)
กล้อง 360 เห็นได้ทั้งโดม แต่โหมด webcam ของมันล็อกค่าแสงไม่ได้ จึงใช้วิธี **อัดวิดีโอไว้ แล้วให้โปรแกรมอ่านไฟล์**

ใช้ได้กับกล้องทุกชนิดที่อัดวิดีโอได้และ **เห็นขอบโดมครบทั้งวงในภาพ**: กล้องแอ็กชัน (เช่น Insta360 Ace Pro 2), กล้อง 360, มือถือเลนส์กว้างพิเศษ

1. วางกล้อง **นอนราบกลางห้อง ให้เลนส์หันขึ้นโดมตรงๆ** (กล้อง 360: รองผ้านุ่มกันเลนส์อีกด้านเป็นรอย) ปิดไฟห้อง
2. ตั้งกล้องเป็น **วิดีโอ 30 fps มุมกว้างที่สุด** และ **ค่าแสงแบบ Manual** ปิดกันสั่น ไม่ใช้ HDR
   - Insta360 Ace Pro 2: โหมด FreeFrame Video, 4K อัตราส่วน 4:3 (หรือโหมด Video มุมกว้างสุด + Stabilization Off)
     มุมกว้างของกล้องตัวนี้พอดีขอบกับห้องนี้: ดูในจอกล้องว่าเห็นขอบโดมครบทั้งวงก่อนอัด
   - กล้อง 360 (Insta360 X3/X4/X5): วิดีโอ 360 ปกติ 5.7K ถ้าเลือกได้ให้ใช้ H.264
   ลองเริ่มที่ ISO 100–200, ชัตเตอร์ 1/30–1/60, white balance คงที่ แล้วดูในจอกล้องว่าโดมตอนฉายขาวไม่ขาวจ้าเกินไป (กด T สองครั้งเพื่อฉายขาว)
3. **กดอัดวิดีโอที่กล้องก่อน** แล้วออกห่างจากกล้อง
4. ที่แผงควบคุม กด **1) ฉายลายให้กล้องอัด** ลายจะฉายราว 3 นาที เริ่มด้วยแสงขาวกะพริบ 3 ครั้ง และจบด้วยแสงขาว 1 ครั้ง
   ฉายลาย **1 รอบต่อการอัด 1 ครั้ง** ถ้ากดยกเลิกกลางทาง ให้หยุดอัดแล้วเริ่มอัดใหม่ก่อนฉายลายอีกรอบ
   ห้ามขยับกล้อง ห้ามเดินผ่าน ห้ามหยุดอัดก่อนจบ
5. หยุดอัด เสียบกล้องเข้าเครื่อง Dell ด้วย USB (เลือกโหมด U-Disk / File Transfer ที่กล้อง) หรือใช้การ์ด microSD
   ก๊อปไฟล์วิดีโอ (นามสกุล `.insv` หรือ `.mp4`) มาไว้ในเครื่อง เช่น `C:\DomePlayer\video`
   ถ้ากล้องเขียนออกมา 2 ไฟล์ต่อการอัด 1 ครั้ง (ชื่อต่างกันตรง `_00_` กับ `_10_`) ให้ก๊อปมาทั้งคู่
6. ที่แผงควบคุม กด **2) เลือกไฟล์วิดีโอ…** แล้วเลือกไฟล์นั้น รอให้อ่านไฟล์และคำนวณ (ไฟล์ 5.7K ใช้เวลาหลายนาที)
   ถ้าขึ้นว่าไม่เห็นภาพจากโปรเจคเตอร์ แปลว่าเลือกไฟล์ของเลนส์ที่หันลงพื้น ให้เลือกอีกไฟล์
7. กด **ดูภาพจากวิดีโอ (ไว้ปรับวงกลม)** แล้วใช้ปุ่มในกรอบ "ขอบวงกลมโดม" ปรับวงกลมให้ทับขอบโดมพอดี แล้วกด **บันทึกวงกลม**
   (โปรแกรมคำนวณใหม่จากข้อมูลเดิม ไม่ต้องอัดใหม่) ช่อง **เลนส์กล้อง** ให้เป็น "ฟิชอาย / กล้อง 360"
8. กด **ตาราง / ขาว / วิดีโอ** ดูผล และ **เปิด / ปิดผล calibrate** เพื่อเทียบ

ทุกครั้งที่เลือกไฟล์วิดีโอใหม่ วงกลมโดมจะถูกหาใหม่อัตโนมัติ (ต้องปรับและบันทึกวงกลมอีกครั้ง) และเลนส์จะถูกตั้งเป็นฟิชอาย

หมายเหตุ: วิธีนี้ทดสอบกับวิดีโอจำลองแล้ว แต่ยังไม่เคยทดสอบกับไฟล์จากกล้อง Insta360 ตัวจริง
ถ้าไม่สำเร็จ กด "เก็บข้อมูลส่งช่าง (zip)" และเก็บไฟล์วิดีโอนั้นไว้ด้วย

### ซ่อม YDome โปรแกรมเล่นโดมตัวเดิมของห้อง (ตั้งแต่เวอร์ชัน 0.3)

YDome เปิดไม่ขึ้นตั้งแต่ 14 พ.ค. 2026 เพราะไฟล์ตั้งค่า 2 ไฟล์ของมัน (`C:\YDome\dome.proj` และ `config.xml` ข้าง `YDome.exe`)
กลายเป็นไฟล์ว่าง (ขนาดเท่าเดิม แต่ข้างในเป็นศูนย์ทั้งหมด) สาเหตุที่เป็นไปได้ที่สุดคือเครื่องดับภายในไม่กี่วินาทีหลังปิด YDome
เพราะ YDome เขียนไฟล์ทั้งสองตอนปิดโปรแกรม ไฟล์ `config.xml` ที่ว่างทำให้ YDome ดับทันทีที่เปิด

ตัวซ่อมแยกออกจาก DomePlayer เป็นโฟลเดอร์ของตัวเองชื่อ `YDome-Fix` (ไม่เกี่ยวกับ DomePlayer ใช้ได้โดยไม่ต้องมี DomePlayer)
ดับเบิลคลิก `YDome-Fix.exe` ในโฟลเดอร์นั้น แล้วกด Yes
- ปุ่มนี้ใส่ไฟล์ที่กู้ไว้แทนไฟล์ที่ว่าง เก็บไฟล์เดิมไว้ในโฟลเดอร์ `files-before-repair-…` และตั้งไฟล์ใหม่เป็น read-only กันพังซ้ำ
- ไม่แตะตัวโปรแกรม YDome และไม่เปิด YDome ให้ ต้องเปิดเองจาก shortcut เดิม
- รายละเอียดและข้อจำกัดอยู่ในไฟล์ `YDome-Fix\อ่านก่อน.txt`
- เปิดได้ทีละโปรแกรม: อย่าเปิด YDome กับ DomePlayer พร้อมกัน และให้ตั้งเปิดเองตอนเปิดเครื่องไว้แค่โปรแกรมเดียว

### ระบบกันพัง (ตั้งแต่เวอร์ชัน 0.2)

ปุ่มในหน้าต่างเริ่มต้น:
- **ตรวจความพร้อม**: ตรวจทุกอย่างใน 30–90 วินาที (ตรวจจากค่าที่เลือกอยู่ในหน้าต่างตอนนั้น) แล้วขึ้นผลเป็นภาษาไทย ✅ ผ่าน / ⚠️ ระวัง / ❌ ไม่ผ่าน พร้อมวิธีแก้
  - การ์ดจอทั้ง 2 ใบและไดรเวอร์, OpenGL ใช้การ์ด NVIDIA
  - เจอจอครบตามที่ตั้งไว้ไหม, ความละเอียดและ Hz เท่ากันไหม, มีจออื่นอยู่ในพื้นที่โดมไหม
  - โปรเจคเตอร์ตัวไหนต่ออยู่กับการ์ดจอใบไหน (จอหลักของ Windows ไม่ต้องย้าย ให้เป็นจอคนคุมเสมอ)
  - **เล่นไฟล์วิดีโอจริงด้วยวิธีเดียวกับตอนฉาย** แล้ววัดว่าเครื่องเล่นทันกี่เท่าของความเร็วจริง (ต่ำกว่า 1.0 = กระตุก)
  - กล้องทุกตัวในเครื่อง: ตัวไหนมีภาพจริง ตัวไหนเป็นกล้องปลอม (NDI) ถ้ากล้องที่ตั้งไว้ไม่มีภาพแต่มีอีกตัวที่มีภาพ จะเปลี่ยนให้เอง
  - ค่า calibrate ยังตรงกับจอตอนนี้ไหม, Screensaver, เปิดเองตอนบูต
  - ผลเก็บไว้ที่ `logs\check.txt` และรูปจากกล้องที่ `logs\check_camera_<เลข>.jpg`
- **ย้อนค่า calibrate…**: ทุกครั้งที่ calibrate ใหม่หรือแก้วงกลมโดม ค่าเดิมถูกเก็บไว้ใน `calibration_backup\` อัตโนมัติ (เก็บ 20 ชุดล่าสุด)
  เลือกชุดที่ต้องการแล้วกด "ใช้ค่านี้" (ค่าปัจจุบันจะถูกเก็บไว้ก่อน ย้อนกลับได้เสมอ)
- **เก็บข้อมูลส่งช่าง (zip)**: รวม log, config, ผล calibrate, รูปจากกล้อง, รายการจอ ไว้ในไฟล์เดียวบน Desktop
- **เปิดเล่นเองทุกครั้งที่เปิดเครื่อง**: ติ๊กแล้วกดเล่น 1 ครั้ง (ไม่ต้องใช้สิทธิ์ admin) ถ้า Windows ต้องใส่รหัสตอนเข้า
  จะเริ่มเล่นหลังใส่รหัส

ระหว่างเล่นมีตัวเฝ้า (watchdog) ดูแลอยู่:
- โปรแกรมปิดไปเองหรือ error → เปิดใหม่ใน 3 วินาที
- ค้าง (ไม่ตอบสนอง 30 วินาที) → ปิดแล้วเปิดใหม่
- วิดีโอหยุดเดินเอง 30 วินาที (ตัวถอดรหัสค้าง) → เปิดใหม่
- โปรเจคเตอร์ถูกปิด/เปิด (จอหายหรือกลับมา) → รอจอกลับมา 15 วินาที แล้วเปิดใหม่ด้วยจอที่มีอยู่ (เครื่องที่หายไปกลับมาเมื่อไร จะเปิดใหม่ให้ครบเองอีกครั้ง)
- ตอนเปิดเครื่อง รอจนโปรเจคเตอร์ครบทุกจอก่อน (สูงสุด 2 นาที) ส่วนตอนกด "เล่น" เองจะเริ่มทันที (ถ้าจอไม่ครบ หน้าต่างเริ่มต้นจะถามก่อน)
- เปิดซ้อนกัน 2 ตัวไม่ได้: กด "เล่น" ขณะที่เล่นอยู่แล้ว โปรแกรมจะถามว่าจะปิดตัวเดิมแล้วเริ่มใหม่ไหม
- กด "เล่น" เองแล้วตัวเล่นเปิดไม่ขึ้น 3 ครั้งติดกัน → หยุดลอง แล้วขึ้นกล่องข้อความบอกสาเหตุ (ตอนเปิดเครื่องอัตโนมัติจะลองต่อไปเรื่อยๆ แบบเงียบๆ)
- ข้อความเตือนตอนเริ่ม (เช่น หาจอไม่เจอ) จะหายจากภาพเองหลัง 2 นาที เหลืออยู่ในหน้า F1 และใน log
- กด **Esc** = ปิดจริง ตัวเฝ้าหยุดด้วย
- Windows จะไม่ sleep และไม่ปิดจอระหว่างเล่น (แต่ Screensaver ต้องปิดเอง)
- บันทึกของตัวเฝ้าอยู่ที่ `logs\watchdog.log`

ก่อน calibrate โปรแกรมกะพริบขาว/ดำทุกเครื่อง 2 รอบ (~12 วินาที) เพื่อ**วัดความหน่วงของกล้อง**
แล้วรอนานขึ้นเองถ้ากล้องส่งภาพช้า และเช็กไปด้วยว่ากล้องมองเห็นแสงจากโปรเจคเตอร์จริง

## 6. อ่านหน้าสถิติ (F1)

```
render fps   60.0   (display 60 Hz, vsync on)   ← ควรเท่ากับ Hz ของจอ
video fps    25.0   (file 25.000)                ← ควรเป็น 25
max gap        50 ms between video frames         ← ที่ 60Hz ปกติจะอยู่ราว 33–50 ms ถ้าเกิน ~80 แปลว่ากระตุก
dropped      mpv 0  decoder 0  delayed 0          ← ควรเป็น 0 หรือเพิ่มช้ามาก
missed vsync 0 total, 0 in last 10 s              ← ถ้าขึ้นเรื่อยๆ แปลว่า GPU วาดไม่ทัน
hw decode    nvdec                                ← สำคัญที่สุด: ต้องขึ้น nvdec (หรือ nvdec-copy)
```

- **hw decode ขึ้นว่า `NONE`** แปลว่ากำลังถอดรหัสด้วย CPU ภาพจะกระตุกแน่นอน ให้อัปเดตไดรเวอร์ NVIDIA แล้วส่ง `logs\domeplayer.log` มาดู
- **hw decode ขึ้น `nvdec-copy`** แปลว่ายังถอดด้วย GPU แต่ต้องก๊อปเฟรมผ่าน CPU ใช้ได้แต่หนักกว่า `nvdec`
- ทุกครั้งที่วนกลับต้นไฟล์ log จะมีบรรทัด `loop N` ถ้ารอยต่อตอนวนกระตุก ให้ดู `max gap` ช่วงนั้น

## 7. ทำให้ลื่นที่สุด (แนะนำให้ลอง)

1. **ตั้งจอหรือโปรเจคเตอร์เป็น 50 Hz** ถ้าเครื่องยอม (Settings → Display → Advanced display → Choose a refresh rate)
   วิดีโอ 25fps บนจอ 60Hz แสดงเฟรมได้ไม่เท่ากัน (สลับค้าง 2 กับ 3 รอบจอ) จะเห็นภาพสะดุดเล็กๆ ตอนภาพเลื่อนช้าๆ
   ที่ 50Hz ทุกเฟรมค้างเท่ากันคือ 2 รอบ ภาพจะนิ่งกว่า (`max gap` ควรขึ้น 40 ms คงที่)
2. **NVIDIA Control Panel → Manage 3D settings:**
   - *Power management mode* = **Prefer maximum performance**
   - *Vertical sync* = **Use the 3D application setting**
3. **Windows:** Power plan = High performance และปิด Sleep / Screen saver
4. Windows Update หรือ notification ที่เด้งขึ้นมาทำให้กระตุกได้ เครื่องใช้งานจริงควรตั้งเวลา Windows Update นอกเวลาเปิดห้อง

## 9. แผนเฟสถัดไป (โครงสร้างโค้ดรองรับไว้แล้ว)

ตอนนี้เฟรมถูกวาดลง texture 3840×3840 ก่อน แล้วค่อยผ่าน shader `VIDEO_FRAG` ใน `domeplayer/app.py`
เฟสต่อๆ ไปจะ**เพิ่มหน้าต่างและ shader** โดยไม่ต้องเปลี่ยนโครงหลัก:

- **เฟส 2 (ทำแล้ว):** โหมด stack: หน้าต่างเดียวคลุมทุกจอ วาดภาพเดียวกันทุกจอ ปรับมุม 4 จุดและความสว่างรายจอ ตารางทดสอบ
- **ถัดไป ถ้าจำเป็น:** mesh warp หลายจุด (ถ้าปรับ 4 มุมแล้วกลางภาพยังไม่ทับกันเพราะความโค้งของโดม)
- **ทำแล้ว (0.2):** เปิดเครื่องแล้วเล่นเอง + ตัวเฝ้า (watchdog) ผ่านช่องติ๊กในหน้าต่างเริ่มต้น ดูหัวข้อ "ระบบกันพัง" (อย่าใช้ Task Scheduler หรือ shortcut `--play` เอง เพราะจะไม่มีตัวเฝ้า)
- **ถ้าหน้าต่างเดียวคลุม 2 การ์ดแล้วกระตุก:** แยกเป็น 2 process (GPU1 = จอ 3,6,2,4 / GPU2 = จอ 5,1)
  ให้ process หนึ่งเป็น master ส่งเวลาเล่นทาง UDP และอีกตัวปรับความเร็วตาม
