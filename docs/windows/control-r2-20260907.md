# Control R2 — Windows verification, 7 September 2026

This patch adds source-format preflight before creating NDI senders. A missing,
ambiguous, changed, differently sized or differently timed input fails with a
specific message instead of silently proceeding into rejected-frame black output.
It does not change Arena composition settings. A project revision change while
checking the source also rejects startup.

The native read-only probe now supports one uninterrupted receive window of
5–600 seconds. `scripts/ndi-continuous-acceptance.mjs` uses this for five parallel
local decoders; it never routes physical receivers or closes Arena.

## Actual full-width source test

- Windows MAPPINGPC, NVIDIA RTX A400, Arena remained running.
- Actual Arena Composition: 8892×1200 at declared 60 fps.
- Five 1920×1200 outputs, identity warp, unity color, no blend maps in this
  capacity diagnostic. Viewports span the real source; saved project is unchanged.
- Five uninterrupted 300-second decode windows: approximately 22.99 fps/channel.
- Source-valid telemetry stayed true, software black stayed false, no reported
  decoder drops or timecode regressions. **60 fps throughput acceptance failed.**
- Content was near black (sparse sampled mean ~0.67/255), so dynamic image
  correctness is NOT verified. This is not a five-projector or LAN acceptance.
- Test senders submitted stop-black and exited. Arena was not closed/restarted.
- Prior 30 fps run against the same 60 fps source was rejected-format black;
  it is explicitly NOT usable performance evidence. The diagnostic now rejects
  this mismatch before starting senders.

## Readiness

`scripts/check-windows-readiness.mjs` checks API, Canon USB enumeration, five
receiver profiles, projector addresses/credential presence and the weekly schedule.
Even a configured result never claims camera-image, optical or power-cycle proof.
Desktop shortcuts on the current PC expose this check and local receiver account
entry. Do not enter the Panasonic projector account as the decoder account.

Latest check: API OK; no Canon USB device, only four NDI Webcam devices; receiver
profiles absent; five projector addresses and actual weekly schedule not configured.
Both known decoder web interfaces (.31 and .34) respond, but no account was guessed.

Tests: local full suite 591 tests / 585 passed / 6 platform skips / zero failures;
Windows focused source-preflight, readiness, save-evidence and DPAPI suite 12/12.
The existing production scheduler is not replaced or enabled by this patch.
Control R2 installer still requires installed Node.js and NDI runtime. Production
promotion, real camera measurement, receiver switch/restore, dynamic full-show load
and actual weekly boot/Save/standby/shutdown remain unverified.
