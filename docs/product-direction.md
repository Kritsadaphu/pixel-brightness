# Pixel Brightness — กรอบงานที่ต้องรักษา

## บันทึกคำยืนยันของผู้ใช้ — 6 กันยายน 2026

ผู้ใช้ย้ำว่า: “คุณอย่าลืมเรื่อง hive screenberry mad mapper นะ”

เก็บ **Hive, Screenberry และ MadMapper** ไว้เป็นผลิตภัณฑ์อ้างอิงในการพัฒนา
Pixel Brightness ต่อไป การแก้ปัญหา R50 USB หรือ NDI ในแต่ละรอบไม่ใช่การลด
ขอบเขตผลิตภัณฑ์ทั้งหมดเหลือเพียงการรับภาพหรือสร้างแพตเทิร์น

ยังไม่มีรายละเอียดในข้อความนี้ว่าต้องการความสามารถใดจากแต่ละผลิตภัณฑ์
จึงไม่ถือว่าผู้ใช้สั่งติดตั้ง เชื่อม API ซื้อไลเซนส์ เลียนแบบหน้าตา หรือรับรอง
ว่า Pixel Brightness ทำได้เทียบเท่าผลิตภัณฑ์ใดแล้ว เมื่อทำ feature comparison
ต้องตรวจเอกสารทางการและแยกข้อเท็จจริงออกจากเป้าหมายของเรา

## ขอบเขตที่ยืนยันแล้วจากงานนี้

- ระบบ projection mapping ที่ใช้ได้กับหลายสถานที่และพื้นผิว ไม่ยึดเฉพาะโต๊ะ/ผนัง
- รับงานจาก Resolume Arena และส่งภาพออกทาง NDI ไปยัง decoder/projector
- Geometry/warp, edge blending, mask, colour และ black-level uniformity
- ใช้กล้องช่วยวัดและปรับอัตโนมัติ โดยแยกผลทดลองออกจากค่าที่นำไปฉายจริง
- Web Control, การบันทึก/เรียกคืนงาน, Projector Control ผ่าน LAN และตารางรายวัน
- ปลายทางห้าโปรเจคเตอร์ overlap 10%; ขณะนี้ทดสอบสองตัวก่อน
- ทดสอบที่บ้าน แต่ใช้คอม Windows เครื่องที่จะนำไปหน้างานจริง

รายการนี้เป็น **ขอบเขตเป้าหมาย ไม่ใช่รายการที่ผ่านการตรวจรับแล้ว**
ต้องแสดงสถานะ implementation, deployment และ physical verification แยกกัน
ผล unit test, NDI loopback หรือ geometry candidate เพียงอย่างเดียวไม่ยืนยัน
ว่า Auto Calibration หรือระบบห้าโปรเจคเตอร์พร้อมหน้างาน

## การรักษาระบบที่ติดตั้งอยู่

ใช้รุ่นพัฒนาแยกและสำรองค่าก่อนทดสอบบนคอมจริง ผู้ใช้อนุญาตให้เปลี่ยนภาพ
Arena ระหว่างทดสอบที่บ้าน แต่ไม่ถือเป็นคำสั่งให้ล้างค่าของเดิม เปลี่ยนไดรเวอร์
หรือปิดเครื่อง การสำรองไฟล์ที่บันทึกแล้วไม่ครอบคลุมการแก้ไขในหน่วยความจำ
